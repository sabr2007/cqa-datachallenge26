# Стенд Dynamics 365: панель оценки качества во вкладке формы обращения

Интерфейс оценки (`embed.html`) работает как **HTML web resource** model-driven app с реальными ограничениями платформы: относительные пути, контекст записи из `parent.Xrm`, язык пользователя, строгий CSP и пересоздание iframe при смене вкладок. Папка `d365/` — макет формы обращения: здесь страница играет роль платформы и держит заглушку `window.Xrm`. В решение Dynamics загружается только панель (`embed.html` + модули) и команда (`js/embed/command.js`).

## Запуск и демо

```bash
uv run uvicorn app.main:app --port 8050
```

- <http://127.0.0.1:8050/d365/> — форма обращения. Вверху переключатели **«Запись»** (диалоги набора DEV) и **«Язык пользователя»** (LCID 1049 / 1087 / 1033).
- <http://127.0.0.1:8050/embed.html?data=group%3DDEV%26conversation%3Dp1-ru-029> — панель отдельно (контекст из `data`).

Сценарий на минуту:
1. Вкладка **«Качество»**: итог, грубая ошибка, секции и критерии с цитатами. `#10` открывает полную карточку на этой реплике.
2. **«Хронология» → «Качество»**: форма уничтожила и заново создала веб-ресурс (справа растёт счётчик загрузок), панель восстановилась. Если оценка шла, новая панель не запускает её повторно, а дожидается результата.
3. Команда **«Оценка качества»** в панели команд: та же панель в боковом диалоге через `Xrm.Navigation.navigateTo`. В ней кнопка **«Оспорить»**: уже оспоренные критерии недоступны в списке. Если апелляцию успели подать из другого окна, сервер отвечает 409, и панель объясняет, что апелляция уже есть.
4. **Язык пользователя → Қазақша**: подписи панели на казахском (`userSettings.languageId = 1087`).
5. **«Создать»**: у новой записи ещё нет id, и панель просит сначала сохранить обращение.

## 1. Какие файлы загрузить как web resources

Префикс издателя — виртуальный корень. Структура после него повторяет `public/`, поэтому относительные ссылки (`app.css`, `js/embed/main.js`, `../api.js`) работают без изменений, в том числе под URL с версией кеша `/%7B<версия>%7D/WebResources/…`.

| Файл в `public/` | Имя web resource (пример с префиксом `cqa_`) | Тип |
|---|---|---|
| `embed.html` | `cqa_/quality/embed.html` | Веб-страница (HTML) |
| `app.css`, `css/embed.css` | `cqa_/quality/app.css`, `cqa_/quality/css/embed.css` | Таблица стилей (CSS) |
| `js/embed/*.js` (10 файлов) | `cqa_/quality/js/embed/<имя>.js` | Скрипт (JScript) |
| `js/api.js`, `dom.js`, `format.js`, `evaluation.js`, `icons.js`, `components/ui.js` | `cqa_/quality/js/<путь>` | Скрипт (JScript) |
| `favicon.svg` (необязательно) | `cqa_/quality/favicon.svg` | Векторный формат (SVG) |

- Всего 20 файлов, около 230 КБ. Лимит на один ресурс по умолчанию 5 МБ (`Organization.MaxUploadFileSize`).
- В именах нет дефисов: имя web resource допускает только буквы, цифры, `_`, `.` и `/`.
- ES-модули (`<script type="module">`) — обычные Script-ресурсы, сборка не нужна. Шрифт системный (в Dynamics это Segoe UI): web resource не умеет хранить файлы шрифтов, а CDN запрещён CSP.
- Загружать пачкой удобно через XrmToolBox → WebResources Manager (папка превращается в ресурсы с теми же путями). Можно и вручную: make.powerapps.com → Решения → Создать → Другое → Веб-ресурс.

## 2. Как добавить панель на форму обращения

1. Добавьте к таблице «Обращение» (`incident`) колонку **`cqa_conversationid`** (однострочный текст). В ней id диалога из контакт-центра, её заполняет интеграция.
2. В конструкторе формы создайте вкладку **«Качество»** с секцией в одну колонку и вставьте HTML web resource `cqa_/quality/embed.html`:
   - включите передачу кода типа и id записи в параметрах: придут `id`, `typename`, `orgname`, `userlcid`;
   - настраиваемый параметр (data): `group=PROD&field=cqa_conversationid`;
   - высота — растягивать на доступное место; подпись можно скрыть.
3. Как панель находит диалог (`js/embed/context.js`). Сначала читает `parent.Xrm.Page.getAttribute(field).getValue()`, затем `getId()` записи, затем `conversation` из `data`, затем параметр `id`. `data` принимается и как JSON `{"group","conversation"}`, и как пары `key=value`, и раскодируется до двух раз: форма кодирует значение сама. Язык берётся из `Xrm.Utility.getGlobalContext().userSettings.languageId` (1049 → RU, 1087 → KZ, 1033 и любой английский → EN), иначе из `userlcid`.
4. Форма может уничтожить и пересоздать веб-ресурс при переходе по вкладкам, поэтому инициализация повторяемая. Каждый экземпляр заново читает контекст и отменяет запросы прежнего. Начатую оценку панель повторно не запускает: в sessionStorage остаётся отметка, а панель опрашивает историю оценок.
5. После оценки или апелляции панель вызывает `formContext.data.refresh(false)`, и итог в шапке формы обновляется без сохранения записи.
6. `Xrm.Page` устарел, но для HTML-ресурса на форме документирован доступ через `parent.Xrm`. Вариант на будущее: в OnLoad и TabStateChange формы передавать `formContext` через `getControl(...).getContentWindow()`. Для этого меняется одна функция `readHostXrm` в `context.js`.

## 3. Команда «Оценка качества» (боковая панель)

Загрузите `js/embed/command.js` как `cqa_/quality/js/embed/command.js`. В конструкторе команд добавьте на форму обращения кнопку: действие «Run JavaScript», библиотека `cqa_/quality/js/embed/command.js`, функция `CQA.openQualityPanel`, параметры `PrimaryControl` и строка с набором (например, `PROD`). Команда делает:

```js
Xrm.Navigation.navigateTo(
  { pageType: "webresource", webresourceName: "cqa_/quality/embed.html", data: "group=PROD&conversation=…" },
  { target: 2, position: 2, width: { value: 480, unit: "px" }, title: "Оценка качества" });
```

На стенде кнопка вызывает этот же файл.

## 4. Адрес API и CSP

- **Адрес API** задаётся атрибутом `data-api-base` у `#cqa-root` в `embed.html` (пусто — тот же origin). Ссылка «Полная карточка» берётся из `data-app-url`: впишите адрес опубликованного приложения CQA. Все запросы панели идут через одну точку, `js/api.js`.
- **CSP панели** (meta в `embed.html`): `default-src 'self'; script-src 'self'; style-src 'self'; connect-src 'self'; img-src 'self' data:; media-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; require-trusted-types-for 'script'`. Это значит: никаких inline-скриптов, стилей и обработчиков в разметке, никакого `eval` и CDN. Trusted Types дополнительно запрещают HTML-строки в DOM, данные попадают только через `textContent`. Политика строже, чем строгий CSP Power Platform: там `style-src` разрешает `'unsafe-inline'`.
- **API на другом домене**, два пути:
  1. **Рекомендуемый: прокси через Dataverse Custom API.** Custom API `cqa_GetEvaluations` / `cqa_Evaluate` / `cqa_CreateAppeal` и плагин, который вызывает бэкенд CQA сервер-сервер (секрет хранится в переменной среды или Key Vault). Браузер ходит только в `/api/data/v9.2/…` своего origin: `connect-src 'self'` не меняется, авторизацию и роли берёт на себя Dataverse. Оценка укладывается в 90 с при лимите плагина в песочнице 2 минуты. В панели меняется только транспорт в `js/api.js`.
  2. **Напрямую.** Укажите `data-api-base="https://cqa.example.com"` и добавьте этот origin в `connect-src` meta-CSP. Если в среде включён строгий CSP Power Platform, origin нужно добавить и в `connect-src` среды (Центр администрирования → среда → Параметры → Конфиденциальность и безопасность). На бэкенде включите CORS для `https://<org>.crm11.dynamics.com` и аутентификацию (токен Entra ID).
- `frame-ancestors` в meta-CSP браузер игнорирует. Встраивание формой разрешает платформа (по умолчанию `'self' https://*.powerapps.com`).

## Что проверено

Сценарии в Chromium (Playwright) на ширине 1440, 1024, 900, 480 и 360 px:

- в консоли 0 нарушений CSP и Trusted Types;
- контекст берётся из `parent.Xrm`, из `data` (JSON и `key=value`) и из `id`; язык — по LCID;
- при смене вкладок iframe пересоздаётся, а оборванная оценка подхватывается;
- апелляция: ответы 201 и 409, проверка пустого комментария;
- ошибки 502, 503 и 504 показаны понятным текстом;
- режим создания записи и некорректный id обработаны;
- страница не прокручивается по горизонтали.

Отдельно сквозной прогон на настоящем API: оценка из вкладки, обрыв iframe на 4-й секунде, сервер досчитал, новая панель показала результат, а шапка формы обновилась через `data.refresh`. Решённые апелляции показаны с причиной и итогом «до/после». Аудит axe-core (WCAG 2.1 AA): 0 нарушений на форме, во вкладках, в панели и в диалоге апелляции.
